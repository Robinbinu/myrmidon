# Messaging channels in Hermes Agent and OpenClaw (2026-10-08)

Asked: "channels support for whatsapp telegram etc just like openclaw and hermes". Both projects were cloned and read;
file references below are into those repos.

## How they are built

Both run one gateway process that loads **one plugin per platform**; the core owns everything platforms share.

| | Hermes Agent (Python) | OpenClaw (TypeScript) |
|---|---|---|
| Adapter | `BasePlatformAdapter`: `connect`, `send`, `edit_message`, `send_typing`, `send_image/voice/document`; inbound via `handle_message(event)` (`gateway/platforms/base.py`) | `ChannelPlugin`: optional adapters `config`, `pairing`, `security`, `groups`, `outbound` (`chunker`, `textChunkLimit`, `sendText/sendMedia`), `gateway.startAccount/stopAccount`, `heartbeat.sendTyping`, `approvalCapability` (`src/channels/plugins/types.plugin.ts`) |
| Registration | `plugins/platforms/<name>/plugin.yaml` + `ctx.register_platform(...)` with required env, setup function, allowlist env, max length | `extensions/<id>/`, manifest `"channels": ["telegram"]`, `defineBundledChannelEntry` |
| Config | env vars in `~/.hermes/.env` over `config.yaml` | `channels.<id>` (with per-account overrides), hot-reloaded |
| Core owns | sessions, auth, chunking, streaming, approvals, delivery ledger | sessions/routing, the `message` tool, chunking, draft streaming, durable ingress |

## Libraries

- **Telegram**: Bot API with long polling by default, webhook optional with a secret header (python-telegram-bot;
  grammY + throttler). A 409 conflict means another poller; restart polling.
- **WhatsApp**: both use **Baileys** (WhatsApp Web multi-device, unofficial) with a QR login; Hermes runs it as a
  Node bridge over HTTP, OpenClaw in-process. Hermes also has the official **Meta Cloud API**. Session credentials
  in a private folder (`creds.json`), to be kept 0700/0600 and never shared.
- Others: Slack (Bolt, Socket Mode), Discord (gateway), Signal (`signal-cli` daemon over HTTP), iMessage (bridge on
  a signed-in Mac), email (IMAP + SMTP), SMS (Twilio).

## Who may talk to the agent

- **Deny by default.** Unknown senders get a **pairing code** (8 characters, no look-alikes, 1 hour, at most 3
  pending, rate-limited, lockout after failures, stored hashed) and their message is **not processed**; the owner
  approves it (`openclaw pairing approve telegram CODE`, or a UI). Hermes switches to silently ignoring strangers
  once an allowlist exists, so the bot's existence is not leaked; email always ignores.
- Policies: DMs `pairing | allowlist | open | disabled`; groups default to allowlist and **mention-only**, with
  unmentioned messages kept only as context; a quote-reply counts as a mention but does not authorize the sender.
- Owner vs others: only owners may run admin commands or approve risky actions (OpenClaw `ownerAllowFrom`, Hermes
  `allow_admin_from`).
- Prompt injection: chat names, display names, quoted text and transcripts are wrapped as untrusted and length-bound;
  bot-to-bot loops are rate-limited (Hermes `BotLoopGuard`). Both warn against "allow all" with terminal access and
  against weak models on untrusted inboxes.

## Sessions and routing

- Replies always go back to where the message came from; the model does not choose (OpenClaw).
- A DM is one conversation; groups are one per group (OpenClaw) or one per user in a group (Hermes default);
  threads/topics add to the key. No automatic reset: `/new` starts fresh.
- In-chat commands: `/new`, `/stop`, `/status`, `/model`, `/approve`, `/deny`, `/retry`, `/undo`.
- A message arriving mid-run: steer (default in OpenClaw), queue, or interrupt — Myrmidon already has steer/queue.

## Long work

- Chunk to the platform limit (~4000), splitting on newlines and keeping code fences balanced, with `(1/3)` marks.
- Progress: one **editable status message** with tool lines, then the final answer as a new message (OpenClaw's
  default `progress`), or a streamed draft edited every ~0.8 s (Telegram allows ~1 edit/s).
- Typing indicator kept alive every 2–3 s, paused while waiting for an approval.
- **Approvals from the chat**: Telegram inline buttons (approve once / always / deny), WhatsApp reactions 👍/👎 or
  `/approve`; expire after 5–30 minutes, and with no way to ask, the default is deny.

## Media

- Inbound files saved to a media store with a size cap; **voice notes transcribed** (local whisper or a provider)
  and the transcript treated as untrusted text. Outbound files from the agent as documents, images, voice notes.

## Reliability

- Durable ingress: each inbound message is stored before it is handled, one lane per conversation, deduplicated by
  platform message id (OpenClaw keeps tombstones 7 days); Telegram's polling offset is saved only after that.
- Delivery ledger: replies go pending → attempting → delivered/failed and are retried after a restart (Hermes marks
  a possibly repeated one).
- Reconnect with exponential backoff and jitter (WhatsApp 2 s → 30 s; Hermes 30 s → 300 s for failed platforms).

## Warnings

- WhatsApp via Baileys is unofficial: use a dedicated number, never message people first, no bulk sending; WhatsApp
  Web changes can break it until the library updates (Hermes). OpenClaw recommends a separate phone/eSIM.
- Telegram's privacy mode hides group messages from bots unless they are mentioned; changing it needs the bot
  re-added.
- Configure access before going live.

## What Myrmidon already has

- `ChatService.send` (steer/queue into a running round, or start one), `onStream` (replies as written),
  `decideApproval`, `stop`, the `ask_user` tool, schedules, and a plugin system whose server code runs in-process
  with settings (including secrets). Missing: a way for plugin code to talk to chats, a channel layer (access,
  sessions, chunking, approvals, ledger), and the platforms themselves.

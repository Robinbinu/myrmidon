# VS Code themes for Myrmidon: which ones, where from, and how they map

Settings → Appearance offers Myrmidon's own looks (System, Light, Dark; still the default) beside VS Code themes
developers love, and imports any VS Code theme file. Searched 2026-10-09.

## Which themes

No source publishes an authoritative, current ranking of VS Code colour themes. The Stack Overflow survey asks about
editors, not themes. Marketplace install counts are the best signal, but third-party sites quote them from different
dates and disagree. Treat these numbers as rough:

- One Dark Pro is the theme most often cited, at 6.7M to 8.9M installs, with Dracula Official at 5.1M to 6.7M
  ([WeAreDevelopers](https://www.wearedevelopers.com/magazine/vs-code-themes),
  [Jit](https://www.jit.io/blog/best-vs-code-themes-2023)).
- Night Owl has over 1.9M installs ([hackr.io](https://hackr.io/blog/best-vscode-themes)). One 2026 guide puts Tokyo
  Night above 8M ([Petronella](https://petronellatech.com/blog/tokyo-night-theme-setup-guide-2026/)). That figure
  is unverified and conflicts with the One Dark Pro numbers.
- Catppuccin, Nord, Gruvbox and Rosé Pine show up across editor-agnostic theme lists and have ports for most tools.
- Developers mostly work in the dark: three quarters of Sourcegraph's engineers did
  ([Sourcegraph](https://sourcegraph.com/blog/workspaces-of-sourcegraph/)). Hence 9 dark and 5 light themes.

**Monokai Pro is not shipped.** It is a paid theme by Wimer Hazenberg: free to evaluate, €14.50 to license
([monokai.pro](https://monokai.pro/vscode)), with no open licence. Myrmidon ships the classic Monokai palette from
VS Code's own MIT-licensed theme instead. Anyone with a Monokai Pro licence can import its `.json`.

The data lives in `apps/web/src/client/themes/palettes.ts`. Each theme keeps only the VS Code keys listed below and
five token colours.

## Mapping VS Code keys onto Myrmidon's tokens

`themeTokens()` in `apps/web/src/client/themes/vscode.ts` does the mapping. It handles built-in and imported themes
the same way. Alpha colours (`#rrggbbaa`) are painted over the editor background first. Every derivation stays in
the theme's own colours: a mix of its background and its text.

| Myrmidon token | VS Code key(s), first found | Derived when missing / adjusted |
| --- | --- | --- |
| `--content` (chat, cards) | `editor.background` | `#1e1e1e` dark, `#fff` light |
| `--window` | `sideBar.background` | content deepened 22% (dark) or 3.5% (light) toward black |
| `--raised`, `--control*`, `--fill*` | (none) | content mixed toward the text by 4–16%, as Myrmidon's own steps |
| `--separator`, `-strong` | (none) | text at 11% / 20% alpha |
| `--material-*` | `menu.background`, `editorWidget.background` for menus | window / content / raised at 82–92% alpha |
| `--label` | `editor.foreground`, `foreground` | lifted toward white (dark) or black (light) until ≥4.5:1 on all eight surfaces |
| `--label-2`, `--label-3` | (none) | text faded 18% / 36% toward the background, but only as far as it still reads at 4.5:1 |
| `--accent`, `--signal`, `--work` | first *chromatic* one of `activityBarBadge.background`, `button.background`, `focusBorder`, `progressBar.background`, `textLink.foreground`; then the `keyword` token colour, `terminal.ansiBlue` | Myrmidon amber |
| `--on-accent` | `activityBarBadge.foreground` / `button.foreground` for that key | the accent may move ≤20% so the theme's ink reads at 4.5:1; else white or near-black |
| `--accent-text`, `--work-ink` | the accent | moved until ≥4.5:1 on content, window, fills, raised and controls |
| `--focus` | the accent | ≥3:1 on window and content (a UI indicator) |
| `--ok`, `--warn`, `--bad` | `terminal.ansiGreen` (or `string`), `editorWarning.foreground` / `terminal.ansiYellow`, `editorError.foreground` / `terminal.ansiRed` | Apple's system colours |
| `--*-soft`, `--*-ink` | (none) | 14% alpha; the ink ≥4.5:1 on the surfaces and on its own soft fill |
| `--bad-fill` | the bad hue | deepened until white reads at 4.5:1 |
| `--bubble`, `--on-bubble` | (none) | content mixed 12–20% toward the accent; text ≥4.5:1 on it |
| `--code-bg` (code blocks, inline code) | (none) | the window, as in Myrmidon's own looks |
| `--edge` (crew map links) | (none) | text halfway to the background, ≥3:1 on the window |
| `--terminal-bg`, `--shell-log-bg` | `terminal.background` | content |
| `--terminal-text`, `-command`, `-error` | `terminal.foreground`, `terminal.ansiGreen`, `terminal.ansiRed` | each ≥4.5:1 on the terminal background |
| `--terminal-muted` | (none) | the terminal text faded 35% toward its background, ≥4.5:1. Not `ansiBrightBlack`, which Solarized makes its darkest shade |
| `--ansi-*` (xterm's 16 colours) | `terminal.ansi*` | none: the shell keeps xterm's defaults |

"Chromatic" means HSL saturation ≥0.3 and lightness between 0.2 and 0.88. That passes over themes whose badge or
button is grey: Night Owl's badge, Monokai's buttons, One Dark's buttons. The token colours (`tokenColors` scopes
`comment`, `string`, `keyword`, `entity.name.function`, `constant.numeric`) serve as fallbacks and colour the
gallery's previews. Myrmidon has no syntax highlighter yet, and adding one would mean a new dependency, so code
blocks take the theme's surface and text colours but not its token colours.

**Never themed:** the brand logo (`--logo-*`), the mascot's screen (`--screen*`, its moods `--mood-*`), worker
colours and shadows. Shadows and the scrim come from the theme's kind: a theme sets `data-theme` to `dark` or
`light`, so every token it leaves out falls back to Myrmidon's look of that kind.

**What contrast costs.** Some themes ship text that fails WCAG AA on their own panels, such as Solarized Light's base00 on
base2. The text there is darkened a little, and for those themes `--label-2` and `--label-3` collapse onto `--label`.
Readable text wins over hierarchy. `tests/themes.test.ts` holds every built-in theme to these ratios.

## How a theme is applied

The choice is kept per browser in `myr-theme`, like light and dark: `system`, `light`, `dark` or `palette:<id>`. The
tokens go into one `<style id="myr-palette">` rule, `:root[data-palette]{…}`, not into inline styles. Two attribute
selectors outrank the dark-tokens block, and a second rule restores the inactive-window selection. The page's
`theme-color` follows the window colour. xterm reads the `--ansi-*` palette again whenever `data-theme` or
`data-palette` changes. The desktop shell draws no colours of its own (`titleBarStyle: 'hiddenInset'`), so it needs
no change.

## Importing

Paste or drop a VS Code theme `.json`. JSON with comments and trailing commas is accepted, since VS Code allows both.
The import keeps the name (control characters stripped, 60 characters at most), `type` (worked out from the
background when missing), the keys above and the five token colours. Only `#hex` values pass. A `url()`, an
expression, a colour name, `rgb()`, a nested object or anything else is dropped and counted. A file with no `colors`,
one that only `include`s another file, or one with no `editor.background` is refused, with the reason shown under the
field. The gateway checks again: `appearance.imported` in `settings.json` accepts only hex values under key-shaped
names, at most 12 themes. The browser's cache of the active imported theme is filtered the same way when read back.

**Marketplace ids are not supported.** Fetching one means the gateway downloads a `.vsix` (a zip) from Microsoft's
marketplace and unpacks it. That adds a new outbound network path and a zip reader on the server, for something a
paste already covers. Download the theme's `.json` from its repository and paste it instead.
